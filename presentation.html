01 / Problem Statement

The Challenge: Job Sequencing & Slot Fragility

Balancing profit maximization against the vulnerability of unexpected slot losses.

FOUNDATION
1. Classic Job Sequencing
  • n jobs with unique ID, deadline d ∈ [1..H], and profit p > 0.
  • Unit execution: Each job requires exactly one discrete time slot.
  • Feasibility: A job must complete on or before its deadline (slot ≤ d).
  • Capacity: One job per slot; unassigned jobs are permanently rejected.
THE BOTTLENECK
2. Slot Fragility Vulnerability
  • Traditional models assume 100% guaranteed slot availability.
  • Real environments face pre-existing blocked slots (k) and random failures.
  • Fragility Risk: A schedule maximizing baseline profit can collapse if a single bottleneck slot fails.
  • Lacking resilience, slot removal triggers cascading job displacements.
OBJECTIVES
3. Dual-Objective Mission
  • Objective 1: Compute maximum baseline profit & slot assignments.
  • Objective 2: Enumerate rejected jobs in strict input order.
  • Objective 3: Detect the Critical Slot whose loss causes maximum profit loss.
  • Tie-break: Deterministically pick smallest slot index on equal loss.

03 / Our Solution

The Dual-Engine Approach: Greedy & Resilience

A unified mathematical framework delivering optimal baseline profit and guaranteed resilience analysis.

TIER 1: OPTIMAL BASELINE
Greedy Profit Maximizer
  • Single Pre-Sort: Sorts all n jobs once by profit descending, breaking ties by ascending Job ID.
  • Latest Feasible Slot Allocation: Scans backward from deadline d down to 1. Claims latest free available slot.
  • Preservation Principle: Using the latest slot preserves earlier slots for jobs with tighter deadlines.
  • Exchange Optimality: Provably optimal via the Greedy Exchange Argument.
TIER 2: RESILIENCE ENGINE
Critical-Slot Search Engine
  • Exhaustive Testing: Iterates through every originally available slot s ∈ [1..H], including empty slots.
  • Isolated Rebuild: Marks slot s unavailable and solves anew from the pre-sorted job list in O(n × H).
  • Exact Delta Computation: Evaluates Loss(s) = BaseProfit - Profit(H \ {s}).
  • Deterministic Tie-Breaker: First maximum wins ties (smallest slot number).

Main Workflow: End-to-End Execution Flow

A 5-stage deterministic pipeline from input ingestion to resilient schedule report.

STAGE 1
Input Parsing

STAGE 2
Pre-Sorting
Sorts jobs once: Profit (↓), Job ID (↑). Order reused everywhere.
STAGE 3
Baseline Solve
Greedy backward slot assignment. Collects baseline profit and rejected jobs.
STAGE 4
Perturbation

STAGE 5

Selects worst-case bottleneck slot. Emits standardized 7-line schema.

05 / Complexity & Proofs

Theoretical Guarantees & Runtime Bounds

Mathematical proof of optimality combined with tight asymptotic complexity bounds.

Complexity Analysis
PhaseTimeSpace
1. Sort jobs onceO(n log n)O(n)
2. Baseline scheduleO(n × H)O(H)
3. Critical rebuildsO(n × H²)O(H)
Total SystemO(n log n + n × H²)O(n + H)
Benchmark Specs: For n ≤ 200, H ≤ 60, total operations ≤ 720,000 (< 2ms latency). Sorting once avoids the naive O(H × n log n) trap.
Proof of Correctness
  • Lemma 1 (Optimality): Placing jobs in latest free feasible slot preserves earlier slots for tighter deadlines without loss of generality.
  • Lemma 2 (Exhaustive Coverage): The lost slot must belong to the original available set. Testing all candidates guarantees identifying the global maximum loss.
  • Lemma 3 (Rebuild Soundness): Rerunning greedy from the pre-sorted list without slot s produces the optimal contingency assignment.
